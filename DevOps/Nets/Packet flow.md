[[XDP]] - позволяет дропнуть пакет / переправить на другой интерфейс / пропустить дальше. Позволяет фильтровать ddos
[eBPF](https://habr.com/ru/companies/selectel/articles/887272/) - пользовательская логика

alloc_skb - socket buffer - структура данных в ядре для хранения сетевого пакета в памяти. iptables, nftables, netfilter, conntrack, приложения работают с skb.

![[Pasted image 20260109111823.png]]


ingress(qdisk) - система управления очередями пакетов. 
Командой `tc qdisk add dev eth0 handle ffff; ingress` можно навесить на eth0 ingress qdisc с дескриптором ffff и после этого добавлять различные фильтры через `tc`. Например, фильтровать запросы по айпишник(до iptable)


bridge_check - ядро решает, перебрасывать как ip-пакет или как ethernet-фрейм. Если передаём на L3, то смещаем указатель на данные ethernet-фрейма (в skb остаются данные L2(mac-address и др.))

В схеме таблицы обозначены зелёным цветом - 
- raw(e.g. маркировка пакетов "nottrack", чтобы те не обрабатыватывались conntrack)
- mangle(правила модификации, поддерживает ttl, tos)
- nat(смотрит только на пакеты, создающие новые соединения, поддерживает dest-nat(PRErouting), source-nat(POSTrouting), маскарадинг и редирект)
- filter(основная таблица по умолчанию)

белым цветом - чейны 
- prerouting(обработка входящих пакетов)
- postrouting(обработка исходящих пакетов)
- forward(перенаправление пакетов, адресованных не нам)
- input(обработка входящих пакетов, адресованных нашему локальному процессу, которые будут отправлены на локальный интерфейс) 
- output(обработка пакетов, сгенерированных нами)

В prerouting приходят пакеты, прошедшие xdp, ingress, skb и bridge_check.
Conntrack - это подсистема netfilter, которая отслеживает состояние сетевых соединений(connection tracking). Другими словами, система запоминает, какие пакеты к каким сетевым сессиям относятся. Ведётся таблица сессий, в которой хранится состояние каждой этой сессии.
