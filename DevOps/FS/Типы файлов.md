В большинстве реализаций файловых систем определены семь типов файлов:
- обычный файлы
- каталоги
- файлы символьных устройств
- файлы блочных устройств
- локальные сокеты
- именованные файлы (FIFO)
- символические ссылки

Определить тип файлы можно с помощью команды `file`

```sh
 $ file /usr/
/usr/: directory
 $ file /bin/sh                                                                                                                                                
/bin/sh: Mach-O universal binary with 2 architectures: [x86_64:Mach-O 64-bit executable x86_64] [arm64e:Mach-O 64-bit executable arm64e]
/bin/sh (for architecture x86_64):	Mach-O 64-bit executable x86_64
/bin/sh (for architecture arm64e):	Mach-O 64-bit executable arm64e
```

Другой способ исследования файлов - команда `ls -ld`

```sh
 $ ls -ld /usr/                          
drwxr-xr-x@ 11 root  wheel  352  4 май 08:39 /usr/
```

Кодирование типов файлов в листинге команды `ls`

| Тип файла                   | Символ | Создаётся командой  | Удаляется командой |
| --------------------------- | ------ | ------------------- | ------------------ |
| Обычный файл                | -      | Редакторы, cp и др. | rm                 |
| Символьная ссылка           | l      | ln -s               | rm                 |
| Каталог                     | d      | mkdir               | rm -r, rmdir       |
| Файл символьного устройства | c      | mknod               | rm                 |
| Локальный сокет             | s      | socket (2)          | rm                 |
| Именованный канал           | p      | mknod               | rm                 |
| Файл блочного устройства    | b      | mknod               | rm                 |

---
#### Обычный файл

Представляет собой последовательность байтов. Файловые системы не налагают ограничения на его структуру. Текстовые документы, файлы данных, программные файлы, библиотеки функций и многое другое – всё это хранится в обычный файлах. К их содержимому возможен как последовательный, так и прямой доступ.

---
#### Каталоги

Каталог хранит именованные ссылки на другие файлы. Специальные ссылки `.` и `..` обозначают сам каталог и его родительский каталог соответственно. Такие ссылки нельзя удалить. В корневом каталоге эти ссылки эквиваленты.

---
#### Жёсткая ссылка

Имя файла в действительности хранится в родительском каталоге, а не в самом файле. На файл можно ссылаться из нескольких каталогов одновременно и даже из нескольких элементов одного и того же каталога, причём у всех ссылок могут быть разные имена. Это создаёт иллюзию того, что файл существует одновременно в нескольких каталогах.

Жёсткие ссылки не могут указывать на файл в другой файловой системе, т.к. жёсткая ссылка ссылается на inode, а inode работает и гарантированно уникален лишь внутри одной файловой системы. Между файловыми системами нет общего пространства inode, соответственно, невозможна и жёсткая ссылка между ними.

Создаётся жёсткие ссылки через команду `ln`. Например, команда `ln oldfile newfile` преобразует имя `newfile` в дополнительную ссылку на файл `oldfile`.

Чтобы узнать, сколько жёстких ссылок существует на данный файл, используется команда `ls -l`

---
#### Символическая ссылка

Симлинк (символическая ссылка) — это специальный файл, который указывает на другой файл или директорию по имени (пути), а не по inode, как жёсткая ссылка.

**Как создать:** `ln -s <цель> <имя_ссылки>`
Например: `ln -s /etc/passwd mylink`

**Как удалить:**  `rm mylink`

**Как узнать, на что указывает:**

`ls -l mylink` или `readlink mylink`

Симлинк может указывать куда угодно: и внутри своей, и в другую файловую систему, и даже на несуществующий объект.

---
#### Файлы символьных и блочных устройств

Файлы устройств позволяют программам получать доступ к аппаратным средствам и периферийному оборудованию системы. Ядро загружает драйверы, которые во всех деталях знают, как взаимодействовать с каждый из устройств, поэтому само ядро может оставаться относительно абстрактным и независимым от оборудования.

Файлы устройств можно рассматривать как шлюзы, через которые ядро передаёт запросы драйверу. 

**Символьное устройство** - это интерфейс для последовательного доступа к устройствам (например, терминал, последовательный порт).
Примеры:  
  - /dev/tty1 — терминал
  - /dev/zero — специальный источник нулей

**Блочное устройство** - это интерфейс к устройствам блочного доступа (диск, флешка, CD и т.д.)
Примеры:
  - /dev/sda1 — раздел жёсткого диска
  - /dev/mmcblk0 — компакт-карта

---
#### Локальные сокеты

Используется для межпроцессного взаимодействия, иногда называют UNIX-сокетами.
Пример:  
  - /tmp/mysql.sock — сокет MySQL сервера
 
---
#### Именованные каналы FIFO

Канал для обмена данными между процессами в формате очереди (FIFO)
Пример:  
  - /tmp/myfifo (можно создать: mkfifo /tmp/myfifo)

Именованный канал обеспечивает одностороннюю потоковую передачу данных между двумя процессами, тогда как UNIX-сокет позволяет двустороннее и более сложное взаимодействие между несколькими процессами.
