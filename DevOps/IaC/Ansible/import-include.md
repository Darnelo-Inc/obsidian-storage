В Ansible import и include позволяют подключать внешние файлы с задачами, но работают по‑разному — главным образом в плане времени обработки и поведения при условиях/циклах.


### Кратко: в чём суть разницы

- **import_* (статический) — подключается на этапе парсинга плейбука** (до запуска задач). Всё «как будто написано в основном файле».
- **include_* (динамический) — подключается во время выполнения**, «по ходу дела».


### Основные директивы

1. **import_playbook** — включает другой плейбук.  
2. **import_tasks** — включает файл с задачами.  
3. **include_tasks** — динамически включает файл с задачами.  
4. **include_role** — динамически подключает роль (есть и import_role, но он реже нужен).

### Ключевые отличия

| Критерий | import_* | include_* |
|--------|------------|-------------|
| Время подключения | На этапе парсинга (до запуска) | Во время выполнения |
| Условия (when) | Применяются к каждой задаче из импортированного файла | Применяются к операции включения (весь файл либо не включается) |
| Циклы (loop) | Не поддерживается (нельзя import_tasks в цикле) | Поддерживается (можно включать разные файлы в цикле) |
| Переменные | Видят переменные, доступные на момент парсинга | Видят переменные, актуальные *на момент выполнения* |
| Производительность | Чуть быстрее (всё известно заранее) | Немного медленнее (подгрузка «на лету») |
| Отладка/вывод | Задачи видны в --list-tasks, выводятся по порядку | Задачи появляются в выводе только при фактическом включении |


### Когда что использовать

#### Используйте import_* когда:
- Нужно статически включить задачи/плейбук (как если бы они были «встроены»).
- Важно, чтобы задачи участвовали в --list-tasks и --check.
- Условия when должны применяться к каждой отдельной задаче внутри включённого файла.
- Нет нужды в циклах над включаемыми файлами.

Пример:
- import_tasks: common_setup.yml
- import_playbook: web_deploy.yml

#### Используйте include_* когда:
- Нужно включать файлы динамически (на основе переменных, фактов, результатов предыдущих задач).
- Нужно использовать циклы (loop, with_items) для включения разных файлов.
- Условия when должны решать, включать файл целиком или нет.
- Вы формируете список задач «на ходу».

Пример:
- include_tasks: "{{ item }}.yml"
  loop:
    - setup_db
    - setup_app
    - setup_nginx

- include_tasks: conditional_tasks.yml
  when: some_fact is defined

### Важные нюансы

1. Переопределение переменных  
   - При import_* переменные берутся из контекста на момент парсинга.  
   - При include_* — из контекста на момент выполнения (могут меняться).

2. Обработчики и теги  
   - import_tasks наследует теги и обработчики из основного плейбука «как есть».  
   - include_tasks ведёт себя аналогично, но динамичнее.

3. Рекурсия и циклы  
   - import_tasks нельзя положить в цикл.  
   - include_tasks можно — это часто используют для параметризованных включений.

4. Совместимость  
   - В старых версиях Ansible был просто include и import; сейчас предпочтительны include_tasks, import_tasks и т. п.
