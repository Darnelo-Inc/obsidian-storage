**Role** (роль) в Ansible — это **структурированный набор задач, переменных, файлов, шаблонов и других ресурсов**, предназначенных для решения конкретной типовой задачи на управляемых хостах (например: установить и настроить веб‑сервер, развернуть базу данных, сконфигурировать мониторинг).

Роль позволяет **упаковать логику автоматизации в повторно используемый, модульный компонент**.

### Зачем нужны роли

- **Повторное использование**: одну роль можно применять в разных плейбуках и проектах.
- **Разделение ответственности**: каждая роль отвечает за свою зону (например, nginx, postgresql, fail2ban).
- **Читаемость и поддержка**: код организован по папкам, понятно, где что лежит.
- **Обмен и экосистема**: множество готовых ролей доступно в Ansible Galaxy.


### Структура роли (основные папки/файлы)  

Типовая роль имеет такую иерархию:
roles/
  my_role/
    defaults/      # переменные по умолчанию (main.yml)
    files/             # статические файлы, которые копируются на хосты
    handlers/     # обработчики (например, перезапуск сервиса; main.yml)
    meta/           # метаданные роли (зависимости, лицензия; main.yml)
    tasks/          # список задач (main.yml, а также дополнительные .yml-файлы)
    templates/  # Jinja2‑шаблоны для генерации конфигов
    vars/            # переменные роли (main.yml)
    tests/           # тесты (опционально)
    README.md  # документация по роли

### Как использовать роль в плейбуке

В плейбуке указываете roles: и перечисляете нужные роли:

- hosts: web_servers
  become: yes
  roles:
    - nginx
    - my_role
    - { role: postgresql, postgresql_version: "14" }  # с переопределением переменных

Можно передавать **переменные** прямо при подключении роли (как в последнем примере).

### Как создать свою роль

1. Вручную: создать папку и подпапки по шаблону выше.
2. Через команду: `ansible-galaxy init my_new_role`

(создаст шаблон роли в текущей директории)

  
### Где брать готовые роли

- **Ansible Galaxy** (https://galaxy.ansible.com) — официальный репозиторий.  
  Пример установки: `ansible-galaxy install geerlingguy.nginx`

- Репозитории GitHub/GitLab (ищите по тегам ansible-role).


### Ключевые особенности

- **Порядок применения**: роли выполняются в том порядке, в котором перечислены в roles:.
- **Наследование и переопределение**: переменные из vars/ имеют более высокий приоритет, чем из defaults/.
- **Зависимости**: можно указать в meta/main.yml, чтобы Ansible автоматически подтягивал нужные роли.
- **Контекст**: роль «видит» переменные плейбука и может их использовать.
