Типы сетей (Network Drivers):
1. **bridge** - виртуальный коммутатор для контейнеров на одном хосте
2. **none** - полная сетевая изоляция (нет сети вообще, только lo)
3. **host** - контейнер использует сеть хоста напрямую (без изоляции)
4. **macvlan** - контейнер получает реальный MAC-адрес в физической сети
5. **overlay** - для связи контейнеров на разных Docker хостах (Swarm/Kubernetes)

Дефолтный маршрут используется, когда не описан более специфичный маршрут для данного ip. `via 10.0.2.2` - это ip шлюза, т.е. куда уходят пакеты, не попавшие под другие маршруты. `dev ens33` - название девайса, куда перенаправить пакеты. `proto dhcp` - метка, показывающая, что маршрут получен от dhcp. `src 10.0.2.135` - это предпочтительный исходный ip для отправки пакеты по этому маршруту. Если у интерфейса несколько маршрутов, то ядро выберет этот. `metric 100` - числовой приоритет, чем меньше, тем приоритетнее.
Подсеть `10.0.2.0/24` с `dev ens33`. `proto kernel` значит, что маршрут создан автоматически ядром при назначении ip интерфейсу. `scope link` означает, что адреса в этой подсети доступны на канальном уровне. `src 10.0.2.135` - предпочтительный исходный ip при выходе в эту подсеть.
Итд...

4. Посмотрим nft
![[Pasted image 20260110135530.png|1200]]

Здесь нужен контекст [[Packet flow]], [[XDP]], [[Iptables]], [[Nftables]]

Рассмотрим таблицу NAT, в ней есть несколько CHAIN-ов, включая "кастомный" CHAIN DOCKER, который был добавлен dockerd-ом. Правило DOCKER срабатывает только для входящих пакетов, пришедших с интерфейса docker0. Т.е. если пакет пришел от контейнера, то делается return без изменения адресов.
CHAIN PREROUTING с приоритетом dstnat - это точка, где делается dstnat(подмена айпи и портов). daddr type local - проверка, является ли адрес назначения локальный. Если да, то трафик перескакивает с цепочки DOCKER, где могут быть правила dstnat, пробрасывающие порт на ip контейнера. Это как раз ловит пакеты, которые пришли снаружи на айпи хоста с проброшенными портами.
CHAIN OUTPUT с dstnat ловит пакеты, сгенерированные на самом хосте(curl localhost:8080). Исключается lo-интерфейс(daddr!=127.0.0.0/8) и если целевой адрес локальный(daddr type local), то прыгаем на DOCKER. Это нужно, чтобы не только внешние запросы заворачивались в DOCKER, но и запросы с самого хоста.
CHAIN POSTROUTING - в нём происходит маскарадинг в srcnat(подмена айпи контейнера на айпи хоста). ip saddr 172.17.0.0/16 - сеть контейнеров docker, также исключаем трафик из docker0. Это позволяет контейнерам ходить в интернет и получать пакеты обратно.

![[Pasted image 20260110195028.png|1200]]
![[Pasted image 20260110195254.png|1200]]

CHAIN DOCKER - блокировка прямого доступа из-вне к контейнерам(дроп пакетов), чтобы не попасть в контейнер, скипнув nat-таблицы.
CHAIN FORWARD - фильтрация транзитного трафика(любой пакет, не прошедший докерские правила будет отброшен)
CHAIN DOCKER-USER - тут можно добавить пользовательские полиси
CHAIN DOCKER-FORWARD - пакеты, пришедшие с docker0, разрешаются наружу
CHAIN DOCKER-ISOLATION-STAGE-(1|2) - двухшаговый механизм, не позволяющий контейнерам одной сети ходить в контейнер другой, если несколько сетей.

Создадим сетевую изоляцию без docker:

1. Создадим bridge
`ip link add name dikiy-ogurec type bridge`

2. Активируем его
`ip link set dikiy-ogurec up`

3. Назначим адрес мосту
`ip addr add 172.31.0.1/16 dev dikiy-ogurec`

4. Создадим veth-пару
`ip link add name kot type veth peer name pes`

5. Подключим кота к мосту
`ip link set kot master dikiy-ogurec`

6. Активируем кота
`ip link set kot up`

7. Создадим сетевой неймспейс
`ip netns add cheburnet`

8. Поднимем в новом ns lo
`ip netns exec cheburnet ip link set lo up`

9. Подключим пса к неймспейсу
`ip link set pes netns cheburnet`

10. Поднимем в новом ns pes
`ip netns exec cheburnet ip link set pes up`

11. Назначим псу ip
`ip netns exec cheburnet ip addr add 172.31.0.2/16 dev pes`

12. Пропишем дефолтный маршрут
`ip netns exec cheburnet ip route add default via 172.31.0.1`

13. Прописываем маскарадинг
`nft add rule ip nat POSTROUTING ip saddr 172.31.0.0/16 oifname != "dikiy-ogurec" masquerade`

14. Прописываем форвардинг на исходящий трафик
`nft add rule ip filter FORWARD iifname "dikiy-ogurec" oifname "eth0" ct state new,related,established accept`

15. Прописываем форвардинг на входящий трафик
`nft add rule ip filter FORWARD iifname "eth0" oifname "dikiy-ogurec" ct state new,related,established accept`

16. Пробросим порты
`nft add rule ip nat OUTPUT tcp dport 6666 counter dnat to 172.31.0.2:1337`
