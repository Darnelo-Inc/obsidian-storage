**Docker** — это платформа, которая позволяет разрабатывать, упаковывать и запускать приложения в изолированных средах, называемых контейнерами.

**Контейнер** – это изолированное окружение для выполнения программ, создаваемых при помощи механизма изоляции процессов ОС. Сам принцип такого предоставления ресурсов ОС приложениям называется **контейнеризацией** и является одним из видом **виртуализации**. 

Ручное создание контейнера, например, через unshare итп, достаточно заморочено, поэтому создали системы управления контейнерами, такие как **Docker** или **LXC**. Разрозненность этих систем привела к созданию OCI, под эгидой которой были согласованы спецификации контейнер-рантайма, который запускает контейнеры, и спецификаций формата образов контейнеров, который рантайм должен уметь считывать. В Linux обе спецификации реализуется утилитой **runc**.

Все контейнеры Docker на хосте совместно используют CPU, RAM и прочие ресурсы. Docker автоматически устанавливает контейнеры, в которых завершились все процессы.

Основные команды:
`docker version`
`docker ps -a` - список контейнеров
`docker images` - список образов
`docker build -f /path/to/OtherDockerfile -t special-image /path/to/context` - собирает образ контейнера по инструкциям из Dockerfile, архивирует контекст и передает к нему доступ контейнеру
`docker run hello-world` - создает и запускает контейнер на основе образа hello-world
`docker run -it <img>` - запуск контейнера на основе образа, i - интерактивно(оставляет stdin открытым), t - tty(создает псевдотерминал внутри контейнера), d - detached(запуск в фоне), --name - задать имея контейнеру, --rm - удалить контейнер после установки
`docker run -p 8080:80 nginx` - публикация порта, роутинг с 8080 компьютера на 80 порт контейнера, -e - добавление переменных среды
`docker rm <id|name>` - удалить контейнер по id или имени
`docker container prune` - удалить все остановленные контейнеры
`docker stop <id|name>` - остановить контейнер
`docker inspect <id|name>` - информация о контейнере
`docker exec -it <id|name> proc_name` - запустить proc_name в уже запущенном контейнере
`docker logs <id|name>` - вывести логи, которые выводил контейнер
`docker commit [OPTIONS] CONTAINER [IMG_NAME[:TAG]]` - создаёт **новый образ**  из существующего контейнера

То, что многие люди называют Docker-образами, на самом деле является образами в формате Open Container Initiative (OCI). Поэтому, если вы загружаете образ из Docker Hub или другого репозитория, вы сможете использовать его с помощью команды `docker`, или в кластере Kubernetes, или с помощью утилиты podman, или любого другого инструмента, поддерживающего спецификацию формата образа OCI.

Маппинг контейнеров и их fs в /var/lib/docker:
`docker inspect $(docker ps -qa) |  jq -r 'map([.Name, .GraphDriver.Data.MergedDir]) | .[] | "\(.[0])\t\(.[1])"'`
