Каждый Docker-образ состоит из набора слоёв (layers), где каждый слой — это snapshot файловой системы, созданный после RUN/COPY/ADD инструкций в Dockerfile.
Слои являются **иммутабельными** (“read-only”): после создания не меняются.

**Типы слоёв:**
- **Базовый слой** — обычно официальный образ (например, ubuntu:22.04, или python:3.10).
- **Промежуточные слои** — добавляются после каждой инструкции RUN/COPY/ADD.
- **Финальный образ** — набор всех слоёв; при запуске контейнера добавляется **записываемый** слой (container layer), — только он “writeable”.

**НО!**
При запуске контейнера docker-образ преобразуется в OCI-бандл, где все слои объединяются в единое корневое файловое дерево(rootfs), а config.json(runc spec) содержит конфигурационные параметры для запуска контейнера. То есть слоёная структура образа обеспечивает его повторяемость и лёгкость обновления, а на этапе использования получаем итоговый бандл – config.json и объединённый rootfs.

---

  UnionFS – это технология объединения файловых систем-слоёв в виртуальную единую, за счёт чего слои переиспользуются для разных контейнеров. Примеры таких FS – overlay2, aufs, btrfs, zfs и др.

- Каждый новый “верхний” слой может:
    - добавлять/изменять/удалять файлы поверх предыдущих,
    - но старый слой физически не меняется.

**Диаграмма:**

Docker image (например, на базе Python):

  ```
Layer N (ваши RUN/COPY/ADD)  | <--- Добавляет только содержимое инструкции

Layer N-1 (ваш RUN pip install)

Layer N-2 (COPY requirements.txt)

Layer N-3 (FROM python:3.10)

...

Layer 1 (FROM scratch)
```

Кэширование слоёв

**Как это работает:**
- Docker по максимуму **использует кэш** уже собранных слоёв, чтобы ускорять сборку.
- Как только встречается инструкция, чей слой уже рассчитан (и все инструкции выше — не изменились), берётся слой из кэша.
- Если на каком-то этапе изменился слой, все следующие пересобираются с нуля!

**Алгоритм:**
1. Docker идёт сверху по Dockerfile.
2. Находит первую инструкцию, где изменились параметры (например, новый файл или новый ENV).
3. До этой строки — кэш, после — подсобирает новые слои (кэш обнуляется).

Также важно удалять файлы в том же слое, где они создаются. 
E.g.
```
RUN cp a.tar . && ... && rm a.tar

а если сделать

RUN cp a.tar . && ...
RUN rm a.tar

то a.tar всё равно попадёт в итоговой образ
```
