### Что такое NUMA‑архитектура


NUMA (Non‑Uniform Memory Access, *неоднородный доступ к памяти*) — это модель памяти в многопроцессорных системах, где:
- время доступа к памяти зависит от расположения памяти относительно процессора;
- память физически распределена по узлам/сокетам, но логически единая (все процессы видят одно адресное пространство).


#### Ключевая идея
- Близкая память (локальная для сокета) — быстрый доступ.  
- Дальняя память (в другом сокете) — медленнее (требуется передача по межпроцессорной шине, например, QPI/UPI/Infinity Fabric).  
- Это отличает NUMA от UMA (Uniform Memory Access), где доступ ко всей памяти одинаково быстрый (как в однопроцессорных системах).


### NUMA per socket = 2: что это значит

Фраза «NUMA per socket = 2» означает: в одном процессорном сокете (физическом разъёме на материнской плате) выделено 2 NUMA‑домена (Sub‑NUMA).


#### Как устроено
1. Сокет — один физический процессор (CPU) с множеством ядер.  
2. NUMA‑домен (Sub‑NUMA, узел NUMA) — локальный фрагмент памяти + группа ядер, которые к нему «ближе».  
3. Если NUMA per socket = 2, то внутри одного CPU:  
   - есть 2 независимых NUMA‑узла;  
   - у каждого — своя локальная память (или часть общей памяти CPU);  
   - ядра внутри узла имеют быстрый доступ к «своей» памяти;  
   - доступ к памяти соседнего узла внутри того же сокета — медленнее (но обычно быстрее, чем к памяти другого сокета).

#### Зачем это нужно
- Масштабирование пропускной способности: несколько NUMA‑доменов позволяют параллельно обращаться к разным банкам памяти, снижая конкуренцию.  
- Снижение задержек: ядра работают с «ближней» памятью, а не со всей системой через одну шину.  
- Оптимизация топологии: особенно важно в CPU с большим числом ядер (например, серверные Xeon, EPYC).


### NUMA‑домены (Sub‑NUMA)


Это базовые единицы NUMA‑топологии — локальные «узлы» памяти и вычислительных ресурсов.


#### Свойства
- Локальная память — память, физически подключённая к этому домену (через свой контроллер памяти).  
- Ядра домена — ядра CPU, для которых эта память «ближняя».  
- Междоменный доступ — когда ядро читает/пишет в память другого домена (локального или удалённого); медленнее из‑за межсоединений.  
- Иерархия:  
  - внутри сокета: домен → сокет;  
  - между сокетами: сокет → система.



#### Пример топологии
Система
├── Сокет 0
│   ├── NUMA‑домен 0 (ядра 0–7, локальная память A)
│   └── NUMA‑домен 1 (ядра 8–15, локальная память B)
└── Сокет 1
    ├── NUMA‑домен 2 (ядра 16–23, локальная память C)
    └── NUMA‑домен 3 (ядра 24–31, локальная память D)
- Ядро 0 (сокет 0, домен 0) быстро читает память A, медленнее — память B (внутри сокета), ещё медленнее — C и D (другой сокет).



### Как это влияет на производительность
- Локальность данных — ключевой фактор: если поток работает с памятью своего домена, задержки минимальны.  
- Перемещение данных между доменами (особенно между сокетами) увеличивает латентность и снижает пропускную способность.  
- Балансировка нагрузки — ОС и гипервизоры стараются размещать процессы и их память в одном NUMA‑домене.  
- Программная оптимизация — приложения (БД, HPC) могут явно управлять размещением памяти (numactl, hwloc, API NUMA).


### Инструменты для анализа NUMA
- lscpu — показывает сокеты, ядра, потоки.  
- numactl --hardware — выводит список NUMA‑доменов, их память и «расстояние» (latency) между ними.  
- hwloc — визуализирует топологию (сокеты, домены, кэши, память).  
- /proc/zoneinfo, /sys/devices/system/node/ — системные файлы с деталями по NUMA.  

- perf, vtune — профилировщики, показывающие NUMA‑промахи и междоменные обмены.



### Итог
- NUMA — модель, где скорость доступа к памяти зависит от её расположения относительно процессора.  
- NUMA per socket = 2 — в одном физическом процессоре (сокете) есть 2 локальных NUMA‑домена с собственной «ближней» памятью.  
- NUMA‑домены (Sub‑NUMA) —


базовые блоки топологии; определяют, какие ядра и память «ближе» друг к другу.  
- Оптимизация под NUMA (размещение потоков и памяти в одном домене) критически важна для высокопроизводительных приложений....
